# Технические решения

## Клиент

- **Движок:** Godot 4.7.2 stable (о. 87).
- **Язык:** GDScript со строгой типизацией, C# не используется (о. 86).
- **Графика:** чистое 2D — `Node2D`, `CharacterBody2D`, `TileMapLayer`, `NavigationRegion2D` (о. 115). Мир в метрах как `Vector2`, уровень рельефа — свойство клетки, а не ось. 3D-представление не планируется (уточнено 2026-11-06).
- **Единицы:** 1 клетка = 1 метр, геймплей хранит только метры и секунды — см. [conventions.md](../conventions.md).

## Настройки

- Хранятся в `settings.json`: `JSON.stringify` / `JSON.parse_string`, встроено в Godot (о. 117).
- Клавиши применяются через `InputMap` (о. 117).
- Настройки применяются из памяти сразу, файл просто сохраняется (о. 103, 117).
- Уже известные пункты настроек:
  - переназначение клавиши рывка (о. 103);
  - отключение тряски камеры (о. 32).

**Открыто:** что ещё хранится в настройках — [вопрос 117](../open_questions_tech.md).

## Данные и сохранения

- Статические данные (герои, карты, биомы) — `Resource` (`.tres`).
- Сохранения игрока — JSON, не `Resource`: подменённый `.tres` при загрузке через `ResourceLoader` может выполнить произвольный скрипт (замечания к черновику).
- Прогресс и сохранения живут на сервере (о. 124, 125).

**Открыто:** слоты сохранений и облако Steam — [вопрос 92](../open_questions_tech.md).

## Сеть

- **EOS (Epic Online Services):** relay и P2P-подключение к хосту, лобби, поиск друзей, кроссплатформенные аккаунты через EOS Connect (Steam, PSN, Xbox, Google, Apple → один профиль), кроссплей (о. 122, 123, 131).
- Бой и игровой трафик идут через хоста и EOS, а не через наш сервер.

**Открыто:** какой community-плагин EOS для Godot брать, синхронизация в коопе (вопрос 89) — [open_questions_tech.md](../open_questions_tech.md).

## Сервер

- **Стек:** Rust (`axum`, `sqlx`, `serde_json`), PostgreSQL с `jsonb` (о. 122, оценка серверной части).
- **Что делает:**
  - хранит аккаунты и общий прогресс;
  - ведёт донатную валюту, покупки и гачу скинов — и только это проверяет;
  - получает короткие запросы: вход, сохранение после забега, покупка, ролл гачи.
- **API без состояния:** все данные в базе, поэтому любой новый экземпляр сразу обслуживает игроков.
- **Масштаб:** 10–20 тыс. игроков всего, не одновременно (о. 126).
- **Обязательно:**
  - проверка платёжных квитанций магазинов (Steam, App Store, Google Play, PlayStation, Xbox) на сервере;
  - лог всех операций с донатной валютой;
  - ежедневные бэкапы базы.

### Хостинг — Fly.io, утверждено 2026-11-04

| Этап | API (Rust) | База | $/мес | Когда переходить дальше |
|---|---|---|---|---|
| 0. Разработка и закрытые тесты | 1 × `shared-cpu-1x · 256MB`, засыпает без запросов | локально у разработчика; на Fly — одна машина `shared-cpu-1x` + volume 1 ГБ без HA | ~$3–5 | перед открытым тестом или релизом |
| 1. Релиз | 2 × `shared-cpu-1x · 256MB` + 2 в резерве (остановлены) | Managed Postgres Basic | ~$45 | CPU базы > 70% в пике или API упирается в лимит shared-CPU |
| 2. Рост | 2 × `shared-cpu-2x · 512MB` + 4 в резерве | Managed Postgres Starter | ~$90–110 | устойчиво тысячи игроков онлайн |
| 3. Большой онлайн | `performance-1x` по нагрузке | Launch | от ~$350 | — |

- Автоскейлинг через прокси Fly: в `fly.toml` `min_machines_running = 1`, `auto_start_machines = true`, `auto_stop_machines = "stop"` и лимит одновременных запросов на машину. Если резерва не хватает, новые машины создаются через Fly Machines API.
- Один регион (Европа) достаточен: API не критичен к задержке.
- С релиза — только managed-база с автобэкапами, потому что в ней донатная валюта.

**Открыто:** проверить числа нагрузочным тестом и перепроверить цены Fly перед запуском — [open_questions_tech.md](../open_questions_tech.md).

## Git

- Репозиторий инициализирован, ветка `main`, есть `.gitignore` и `.gitattributes` (о. 91).
- Git LFS не нужен: ассеты пиксельные и лёгкие, ~20 МБ (о. 91).
- Пока тайлы Sprout Lands не заменены или не куплена коммерческая лицензия, репозиторий нельзя делать публичным (о. 91).
