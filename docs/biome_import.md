# Импорт биома из тайлов

Импортёр собирает биом из папки с листами тайлов. Он сам находит на листах тайлы автотайлинга и пропсы и создаёт тему (`TileTheme`), атласы пропсов (`PropAtlas`), пропсы (`PropDef`) и биом (`BiomeData`). Вручную задаётся только то, чего нельзя понять по пикселям: имена пропсов, что из них блокирует проход, где лестница.

Код: `src/dungeon/import/` (`BlobScanner`, `PropSlicer`, `BiomeImporter`), запуск — `tools/import_biome.gd`.

## Запуск

1. Положить листы в папку, например `tiles/biomes/swamp/`, и при необходимости добавить `biome.cfg` (см. ниже).
2. Дать Godot импортировать новые картинки: открыть проект в редакторе или выполнить
   ```bash
   godot --headless --path . --import
   ```
3. Посмотреть, что найдётся, ничего не записывая:
   ```bash
   godot --headless --path . -s res://tools/import_biome.gd -- res://tiles/biomes/swamp --dry-run
   ```
   Отчёт перечисляет листы (сколько форм из 47 найдено, сколько вариантов) и каждый пропс: id, клетка на листе, размер, блокирует ли, коллизия.
4. Записать:
   ```bash
   godot --headless --path . -s res://tools/import_biome.gd -- res://tiles/biomes/swamp
   ```
   Биом сразу появляется в просмотрщике (клавиша `B` или `--biome=swamp`).

Ключ `--out=res://другая/папка` пишет результат не в `res://data`.

## Что создаётся

| Файл | Содержимое | При повторном импорте |
|---|---|---|
| `data/themes/<id>.tres` | тема: листы земли, дорог, обрывов, вода, мост | пересоздаётся |
| `data/themes/atlases/<id>_<лист>.tres` | атлас пропсов одного листа | пересоздаётся |
| `data/props/<id>/<пропс>.tres` | пропсы | пересоздаются; файлы пропсов, которых больше нет, удаляются |
| `data/biomes/<id>.tres` | биом | параметры генерации (рельеф, вода, граница, `lush_amount`…) **сохраняются**, заменяются тема, правила пропсов и деревья границы |

Источник правды — картинки и `biome.cfg`. Тему и пропсы руками не правят: правки пропадут при следующем импорте. Всё, что нужно поменять, задаётся в манифесте. Параметры генерации, наоборот, настраиваются в редакторе прямо в файле биома.

## Как распознаются тайлы

### Листы автотайлинга (земля, дороги, обрывы)

Порядок тайлов на листе не важен: форма каждого тайла читается по его пикселям.

- **Цвет заливки** — самый частый непрозрачный цвет листа (основной цвет травы, песка, снега).
- **Сторона тайла соединена**, если пиксели вдоль неё — «поверхность»: непрозрачные и близкие к цвету заливки. Прозрачный край, кромка берега и склон обрыва читаются как открытая сторона.
  - Север и юг — середина верхнего и нижнего ряда пикселей.
  - Запад и восток — верхняя часть левого и правого столбца, потому что внизу тайла обрыва нарисован склон.
  - Углы — угловой пиксель.
- Из 8 сторон получается маска соседей, как в `BlobAutotile`. Для каждой маски берётся первый тайл с ней (по строкам сверху вниз).
- Результат записывается как `layout_origin` (самый частый сдвиг относительно стандартной раскладки 11×5) плюс `layout_overrides` для остальных. Перепутанные местами формы, как 119/221 в `Hills.png`, распознаются сами.
- **Варианты.** Остальные полные тайлы становятся вариантами:
  - почти без рисунка → `plain_variants`;
  - с заметным рисунком (кочки, цветы) → `lush_variants`;
  - если рисунок заходит на край тайла, это кусок картинки из нескольких тайлов. Такой тайл пропускается, потому что поодиночке он даёт швы.
- Если каких-то из 47 форм нет, импорт останавливается с ошибкой и списком масок.

Проверено на всех листах земли, дорог и обрывов из обоих паков Sprout Lands: распознанные формы совпадают с ручными темами во всех 47 случаях (`tests/test_biome_import.gd`).

### Пропсы

- **Спрайт** — группа соприкасающихся непрозрачных пикселей. Группы, чьи прямоугольники в тайлах пересекаются, считаются одним спрайтом (например, цветок с отдельными лепестками). Спрайты должны стоять по сетке тайлов, как в тайловых паках.
- **Размер** пропса — прямоугольник спрайта в тайлах. Опорная клетка — левая нижняя.
- **Блокирует ли.** По умолчанию блокирует всё, что больше одной клетки, и одиночные спрайты, у которых непрозрачно больше 40% нижнего тайла. Пропсы на воде не блокируют. Это лишь догадка: её поправляют ключи `walkable` и `blocking`.
- **Коллизия** — по основанию спрайта (нижние 4 ряда пикселей):
  - ширина — 85% основания;
  - высота — 0.6 от ширины, в пределах 0.25…0.5 м;
  - `collision_lift` — прозрачный зазор под основанием.
- **Id** по умолчанию — `<лист>_<x>_<y>` по клетке на листе. Имена задаются в манифесте.
- **Правила разброса** по умолчанию:

  | Пропс | Плотность | Кучность |
  |---|---|---|
  | деревья (высота 2) | 0.02 | 0.8 |
  | большие деревья (высота 3+) | 0.006 | 0.9 |
  | блокирующие 1×1 | 0.008 | 0.4 |
  | проходимые | 0.02 | 0.4 |
  | на воде | 0.03 | 0 |

- **Деревья границы** по умолчанию — все блокирующие пропсы высотой от 2 клеток, крупные первыми.

## Манифест `biome.cfg`

Формат — `ConfigFile` Godot: секции `[имя]`, значения в синтаксисе Godot (`Vector2i(9, 5)`, `Rect2i(0, 5, 11, 20)`, словари `{"ключ": значение}`, массивы `[...]`), комментарии через `;`. Пути картинок — относительно папки биома или полные `res://`.

**Без манифеста** листы берутся по именам файлов:
- `land.png`, `road.png`, `hills.png`, `water.png`, `bridge.png`;
- `props*.png` — пропсы на суше;
- `water_props*.png` — пропсы на воде.

| Секция | Ключ | По умолчанию | Смысл |
|---|---|---|---|
| `[biome]` | `id` | имя папки | id биома и имена файлов |
| | `display_name` | id | название в игре |
| | `tile_size` | 16 | размер тайла в пикселях на всех листах |
| | `template` | — | биом, из которого копируются параметры генерации при первом импорте |
| | `tint` | белый | оттенок |
| `[land]`, `[road]`, `[hills]` | `texture` | `<секция>.png` | лист автотайлинга; без `[road]` дорог нет |
| | `region` | весь лист | `Rect2i` в тайлах: где искать, если на листе несколько наборов |
| | `lush` | `true` | `false`: все варианты считаются простыми |
| | `plain_variant_chance` | 0.15 | как часто рисуется простой вариант |
| `[hills]` | `stairs` | `Vector2i(9, 5)` | левый верхний тайл лестницы 2×2 (исключается из поиска) |
| | `face_depth` | 0.5 | глубина склона в клетках (см. `TileTheme.cliff_face_depth`) |
| `[water]` | `texture`, `frames`, `fps` | `water.png`, ширина/тайл, 3 | кадры анимации в один ряд |
| `[bridge]` | `texture`, `vertical`, `horizontal` | `bridge.png`, как в `TileTheme` | тайлы начала, середины и конца моста |
| `[props.<лист>]` | `texture` | `<лист>.png` | лист пропсов; секций может быть сколько угодно |
| | `placement` | `"land"` | `"water"` — пропсы на воде |
| | `names` | — | `{"x,y": "id"}`: имя пропса по клетке его левого верхнего тайла |
| | `skip` | — | клетки `"x,y"` или id, которые не импортировать |
| | `walkable`, `blocking` | — | id, которые точно проходимы или точно блокируют |
| | `border` | авто | id деревьев границы (собираются из всех листов) |
| | `density`, `clustering` | авто | `{"id": число}` для правил разброса; плотность 0 — пропс не разбрасывается |
| | `collision` | авто | `{"id": Vector2(ширина, высота)}` в метрах |

Пример со всеми ключами — `tests/fixtures/pine_import/biome.cfg`: он собирает хвойный лес из листов Sprout Lands, и его результат совпадает с ручным `pine_forest`.

## Требования к арту

- **Один размер тайла** на всех листах биома. Размер любой: рендерер масштабирует тему по `texture_tile_size`.
- **Прозрачность там, где местности нет.** Иначе края не прочитать. Сплошная подложка под листом ломает распознавание.
- **Заливка — самый частый цвет листа.** Если на листе больше всего, например, воды, нужно задать `region`.
- **Обрывы:** склон рисуется в нижней части тайла, лестница — блок 2×2 на том же листе.
- **Мост и вода** раскладываются как в базовом паке (или задаются ключами секций).
- **Пропсы стоят по сетке** и не касаются друг друга пикселями.

## Ограничения

- Смысл пропса (дерево это или камень) по пикселям не определить: блокировку, имена и деревья границы лучше проверить по отчёту `--dry-run`.
- Деление полных тайлов на простые и пышные — эвристика по количеству рисунка. Её можно отключить через `lush = false` или задать область через `region`.
- Склон обрыва, лестница и мост не распознаются: их раскладка фиксирована.
- Анимированные пропсы не поддерживаются: каждый кадр станет отдельным пропсом. Лишние кадры убираются через `skip`.
